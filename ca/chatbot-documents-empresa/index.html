01 — Respostes amb evidència

Pregunta als teus documents i rep / una resposta amb fonts.

Un chatbot genèric respon amb coneixement general. Un chatbot documental usa RAG per localitzar fragments rellevants dins del corpus autoritzat, redactar una resposta i mostrar el document d'origen perquè l'equip la pugui comprovar.

// doc_01 Suport intern

L'equip pregunta.

Procediments, polítiques, manuals de producte. En comptes d'interrompre un company, l'equip pregunta al chatbot i rep la resposta amb el document exacte.

// doc_02 Normativa

Respondre segons les regles.

Atenció que s'ha d'ajustar a un reglament, unes bases o un contracte. El chatbot respon citant l'article, no de memòria. Útil per a entitats i AAPP.

// doc_03 Onboarding

Qui acaba d'entrar.

Una persona nova té cent dubtes i no sap a qui preguntar. El chatbot li dona context sobre processos i eines sense gastar el temps de la resta de l'equip.

// doc_04 Coneixement

Anys de documents.

Informes, actes, especificacions acumulades durant anys. El chatbot les fa consultables en llenguatge natural, sense haver de recordar en quina carpeta era allò.

02 — Inventari documental

Quina documentació pot consultar.

L'abast pot incloure PDF, Word, bases de coneixement, intranets i altres repositoris interns. Abans de prometre compatibilitat revisem una mostra, el volum, la qualitat, les versions i els permisos d'accés.

// font_01Documents

PDF i Word.

Manuals, procediments, contractes, plecs o normativa amb text digital i una estructura prou consistent.

// font_02Repositoris

Coneixement intern.

Bases de coneixement, intranets i carpetes corporatives, sempre que hi hagi una via d'accés autoritzada i mantenible.

// font_03OCR

Escanejats, si són llegibles.

Els documents escanejats poden requerir OCR. En validem la qualitat perquè taules, segells o pàgines deteriorades poden degradar la recuperació.

// font_04Governança

Una versió de referència.

Si dos documents es contradiuen o estan desactualitzats, el chatbot no pot decidir quin mana: definim vigència, propietari i font oficial.

03 — Permisos i control

Com protegim els permisos / i reduïm respostes no fonamentades.

RAG redueix el risc en obligar el sistema a buscar evidència abans de respondre, però no converteix la IA en infal·lible. Dissenyem controls per citar, abstenir-se, registrar i escalar a una persona quan la consulta ho exigeix.

// rag_01 Cita

Resposta amb font visible.

Les respostes acceptades mostren el document i el fragment recuperat. En pots comprovar el suport en comptes de fiar-te'n a cegues.

// rag_02 Abstenció

Si falta evidència, s'absté.

Configurem llindars i respostes de sortida perquè digui «no ho sé amb aquests documents» o derivi la consulta quan el suport recuperat no és suficient.

// rag_03 Permisos

Cadascú veu el seu.

L'abast pot integrar identitat i permisos durant la recuperació. Definim denegació per defecte, traçabilitat i proves per comprovar què pot consultar cada perfil.

// rag_04 Revisió humana

El que és sensible, ho revisa una persona.

Consultes legals, contractuals, fiscals o amb impacte operatiu no s'haurien de resoldre a cegues: definim quines respostes requereixen validació humana.

04 — Barcelona i Catalunya

Implantació de chatbot documental / a Barcelona i Catalunya.

Treballem des de Barcelona amb empreses, entitats i administracions. Fem la sessió inicial presencial a Barcelona i la seva àrea metropolitana quan aporta valor, i desenvolupem, despleguem i donem suport en remot per a tot Espanya. El projecte el dirigeix Mike Pérez, Enginyer de Solucions d'IA.

// fase_01Descoberta

Inventari i usuaris.

Mapem documentació, metadades, responsables, preguntes reals, permisos i decisions que el sistema mai no ha de prendre tot sol.

// fase_02Validació

Provar abans d'escalar.

Construïm un corpus acotat i un conjunt d'avaluació amb preguntes reals, mètriques de recuperació, cites, abstencions i criteris d'acceptació.

// fase_03Producció

Integració i seguiment.

Connectem el canal acordat, registrem consultes i traces, controlem costos i revisem errors per millorar el sistema.

05 — Encaix del cas

Quan compensa implantar / un chatbot documental.

No compensa per tenir molts PDF, sinó quan hi ha una necessitat recurrent, un corpus governable i una millora que l'equip pot comprovar.

// senyal_01Repetició

Les mateixes preguntes.

Suport, operacions o persones responen una vegada i una altra consultes que ja estan documentades.

// senyal_02Cerca

Trobar la versió correcta.

L'equip perd temps recorrent carpetes, intranets o documents llargs per localitzar una resposta concreta.

// senyal_03Dependència

El coneixement viu en una persona.

Quan aquesta persona no hi és, costa interpretar on cal buscar o quin procediment continua vigent.

// senyal_04Evidència

La resposta s'ha de justificar.

Normativa, contractes i procediments requereixen veure la font, no acceptar una resposta sense suport.

06 — Diagnòstic documental

Què necessitem per preparar / un diagnòstic.

Partim d'evidència, no d'una demo genèrica. Si el problema encara no està delimitat, comencem per una consultoria d'IA per a empreses que prioritzi el cas correcte.

// input_01Mostra

Documents representatius.

Una mostra petita però real, incloent-hi formats difícils, versions antigues o contingut escanejat si n'hi ha.

// input_02Accés

Usuaris i permisos.

Qui pregunta, què pot consultar cada perfil i quina informació ha de quedar fora del corpus.

// input_03Preguntes

Consultes reals.

Preguntes freqüents, ambigües i sense resposta per avaluar recuperació, abstenció i utilitat.

// input_04Sistemes

Canals i integracions.

Web, intranet, Teams, CRM o altres sistemes on l'equip necessita consultar o registrar la resposta.
